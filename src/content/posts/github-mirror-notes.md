## 一切的起因

博客托管在 GitHub Pages 上，好处是免费，坏处是——**国内访问真的看缘分**。

有时候打开还挺快，有时候图片加载半天，转圈转到怀疑人生。最气的是，自己在电脑上改完代码推上去，想看效果，结果页面半天刷不出来 (；´д｀)

于是就开始折腾"怎么绕路"。

## 我试过的几条路

### 1. 换镜像站

GitHub 的很多资源（比如 release 下载、仓库里的图片），都有国内镜像可以走。

思路很简单：**把下载地址里的 github.com 换成镜像域名**，速度立马不一样。

实测下来：
- 有的镜像稳，有的镜像时好时坏；
- 下载大文件用镜像真香，小文件就无所谓了。

### 2. PCL 多线程下载

这个要特别提一下。

有些文件（比如整合包、客户端、大资源包），镜像也不给力的时候怎么办？

我后来发现 **PCL 启动器** 自带多线程下载——对，就是那个 MC 启动器。它下载比自己用浏览器下快多了，还支持断点续传。

所以现在的流程变成：
1. 先试国内镜像，能下就下；
2. 镜像不行，就拿到直链，丢给 PCL 多线程下载，速度飞起 (๑•̀ㅂ•́)و✧

### 3. 能本地验证的，先本地验证

这个算是最治本的绕路：

代码改完，先在本地把页面跑起来看效果，确认没问题再推上去。这样线上到底快不快，就不那么影响我干活了——反正最后还是要推的，但至少**等待的焦虑**少了很多。

## 折腾完的感想

GitHub 快不快这事，一时半会儿解决不了，但"绕路"的思路是通用的：

**哪里堵，就从哪里绕过去，总有一条路能走通。**

现在我的心态已经放平了：能直连就直连，不行就走镜像，再不行就 PCL 上场，反正总有办法 (ᐡ •͈ ·̫ •͈ ᐡ)

要是你也有类似的烦恼，希望这篇能给你点思路~
